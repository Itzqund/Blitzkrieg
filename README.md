# Блицкриг

**Блицкриг** — приложение-компаньон для Geometry Dash. Оно помогает планировать прохождение уровня по этапам и ранам, отмечать прогресс, записывать попытки и заметки, а также синхронизировать таблицы с сохранениями внутриигрового мода.

**Текущая версия:** `0.2.0-alpha`  
**Состояние проекта:** предварительная версия. Перед обновлением приложения или работой с важными сохранениями рекомендуется иметь отдельную копию исходного JSON-файла.

## Возможности

### Таблицы и раны

- Несколько таблиц уровней с этапами и ранами.
- Редактирование диапазонов, отметок выполнения, количества попыток и заметок.
- Автоматическая сумма попыток всех ранов в строке соответствующего этапа.
- Последовательное закрытие ранов и этапов с проверкой порядка выполнения.
- Сохранение точных значений диапазонов в БД. В интерфейсе проценты отображаются с округлением вниз.
- Ручное изменение порядка таблиц и сохранение порядка при перезапуске.
- Автоматическое обновление данных без сброса позиции прокрутки.

### Генератор блицкрига

- Создание этапов по введённым стартовым позициям.
- Копирование стартовых позиций и результата в буфер обмена.
- Вставка стартовых позиций из буфера обмена.
- Очистка полей генератора.
- Переключение панели генератора без полного пересоздания таблиц.

### Синхронизация с внутриигровым модом

- Привязка таблицы к JSON-сохранению по корневому `id`.
- Использование `profileName` сохранения как названия уровня.
- Двусторонняя синхронизация при запуске и автоматическая проверка раз в минуту.
- Мод имеет приоритет для игровых данных; заметки из приложения сохраняются как данные приложения.
- Изменения из приложения откладываются, пока запущен Geometry Dash, чтобы не перезаписывать файл во время игры.
- Запись компактного JSON в одну строку, без форматирующих отступов.
- Сохранение незнакомых приложению полей JSON для совместимости с модом и будущей статистикой.
- Хранение до трёх последних проверенных резервных копий каждого связанного сохранения в SQLite.
- Если исходный JSON отсутствует или повреждён, приложение может работать по резервной копии и показывает уведомление. Оригинальный файл автоматически не перезаписывается.
- Повторная привязка того же корневого `id` не создаёт дубликат таблицы.

### Интерфейс и настройки

- Несколько тем оформления: Blue, Charcoal и Emerald.
- Русский и английский языки интерфейса.
- Изменение масштаба интерфейса, в том числе сочетаниями `Ctrl` и `+`, `-` или `0`.
- Сохранение темы, языка, масштаба, положения и размеров окна между запусками.
- Восстановление окна в максимизированном состоянии, если оно было таким при закрытии.
- Увеличенная область захвата для изменения размера окна.
- Настраиваемая ширина рабочих столбцов; столбец заметок автоматически расширяется под содержимое и не имеет ручного разделителя ширины.

## Установка

1. Скачайте архив нужной сборки из раздела **Releases** репозитория.
2. Распакуйте архив в отдельную папку.
3. Запустите `BlitzkriegWPF.exe`.

Приложение рассчитано на Windows и использует WPF на `.NET 10`. Для запуска сборки в зависимости от способа публикации может понадобиться установленный .NET Runtime. Для обычного пользователя предпочтительно скачивать готовый архив из Releases, а не отдельные исходные файлы.

## Сборка из исходников

1. Откройте `BlitzkriegWPF.csproj` в Visual Studio с поддержкой WPF и .NET 10.
2. Восстановите NuGet-пакеты.
3. Соберите проект для `win-x64`.

Файл `BlitzkriegDB.db.sql` описывает создание чистой базы данных. При запуске приложение самостоятельно создаёт или обновляет пользовательскую базу, поэтому вручную запускать этот SQL-файл для обычной установки не требуется.

В `ingame_mode_save_file_example.json` лежит пример структуры сохранения мода. Это образец для разработки, а не резервная копия пользовательского сохранения.

## Где хранятся данные

- **База данных:** `%LocalAppData%\Blitzkrieg\BlitzkriegDB.db`.
- **Настройки приложения:** `%LocalAppData%\BlitzkriegWPF\settings.xml`.
- **Резервная копия перед миграцией старой БД:** рядом со старым файлом базы данных.

При обнаружении базы старого расположения приложение переносит данные в новую схему. Перед миграцией создаётся отдельная копия исходного файла БД.
